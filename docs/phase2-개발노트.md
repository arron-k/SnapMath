## 1. 한눈에 보기

Phase 1에서는 **눈에 보이지 않는 "정확도 두뇌"**(사진을 읽고 → 풀고 → 검산하는 엔진)를 만들었습니다.
Phase 2의 목표는 그 두뇌에 **아이가 직접 보고 만지는 "얼굴과 손"**을 입히는 것이었습니다.

> **"사진 한 장이 살아있는 학습 경험이 되도록."**

같은 정답이라도 차가운 글자 더미로 주면 아이는 흥미를 잃습니다.
그래서 또래 친구 **"스냅이"(🦊)**가 말을 걸고, 풀이가 한 줄씩 살아나고, 수식이 교과서처럼 또렷하게 보이도록 만들었습니다.
단, **재미가 정확성을 해치지 않는 선**에서만 — 자신 없는 답은 끝까지 솔직히 "모른다"고 말합니다.

## 2. 아이가 겪는 여정 (전체 흐름)

화면 맨 위에는 **진행 단계바**가 항상 떠서 "지금 어디인지"를 보여줍니다:
`① 사진 → ② 영역 지정 → ③ 문제 확인 → ④ 풀이` (완료=✓초록, 현재=파랑, 작업 중이면 빙글 아이콘).

```
 🦊 홈 화면 — "안녕, 나는 스냅이야!"
      │   [📷 사진 찍기]   [🖼 사진 올리기]
      │   🛡 "사진은 문제 읽는 데만 쓰고 저장 안 해요"
      ▼
 ┌──────────────────────────────────────────────┐
 │ ✂️ ② 영역 지정 — "풀고 싶은 문제를 네모로 콕!"      │
 │    사진 위에 사각형을 드래그/리사이즈              │
 │    [이 부분 풀기]  [전체 사용]  [다시 고르기]       │
 └──────────────────────────────────────────────┘
      │   (지정 영역만 잘라 분석 — 인라인 "읽는 중…" 점3개)
      ▼
 ┌──────────────────────────────────────────────┐
 │ ❓ ③ 문제 확인 — "이 문제 맞아?"                  │
 │    (크롭된) 미리보기 + 읽어낸 문제 (큰 글씨)        │
 │    [✓ 응, 맞아!]   [↺ 다시 찍을래]               │
 │   ▸ 사진이 흐리면 → "한 번 더 찍어줄래?" (재촬영)   │
 └──────────────────────────────────────────────┘
      │ "응, 맞아!"  (인라인 "푸는 중…" 점3개)
      ▼
 ┌──────────────────────────────────────────────┐
 │ ✏️ ④ 풀이 — 한 줄씩 1.5초 간격으로 떠오름          │
 │    ① ② ③ … 교과서 모양 수식으로                   │
 │    마지막에 ✨ "정답: 7개" 강조                    │
 │   ▸ 검산 실패(verified=false)면                  │
 │     "이 문제는 자신이 없어, 선생님께 물어보자"       │
 └──────────────────────────────────────────────┘
```

이 모든 화면은 하나의 **"상태 신호등"**으로 흐릅니다:
`대기(idle) → 영역 지정(cropping) → 읽는 중(reading) → 확인(confirming) → 푸는 중(solving) → 완료(done)`.
로딩(읽는 중·푸는 중)은 전체화면을 가리지 않고 **해당 단계 카드 안에서 인라인**으로 표시돼, "메인으로 돌아갔다 결과로 점프하는" 혼란이 없습니다.
신호등이 바뀌면 그에 맞는 화면이 나타나는 구조라, 나중에 새 단계를 끼워 넣기 쉽습니다.

## 3. 기능 단위별로 무엇을 만들었나

### [2-1] 디자인 시스템 셋업 — "레고 블록 세트"

화면마다 버튼·카드를 매번 새로 그리지 않도록, 공통으로 쓸 **블록 세트**를 먼저 만들었습니다.

- **버튼** — 크고 둥글며, 손을 올리면 살짝 커지고 누르면 들어가는 "말랑한 손맛". 파랑(주요)·노랑(포인트)·외곽선(보조) 3종.
- **카드** — 둥근 모서리의 정보 상자(문제·풀이·도전을 각각 담음).
- **로딩 표시** — 빙글 도는 스피너 + 통통 튀는 점 3개.
- **밝기 토글** — ☀️ 밝게 / 🌙 어둡게 / 🖥 시스템 자동. 새로고침해도 기억되고, **화면 깜빡임 없이** 처음부터 올바른 밝기로 뜸.

> 🔧 개발자 메모: `globals.css @theme` 디자인 토큰 + `class` 다크모드. 무플리커는 `<head>`에 인라인 스크립트(`ThemeScript`)로 첫 페인트 전 클래스를 적용. 컴포넌트는 `src/components/ui`, `theme` 아래. 모션은 `framer-motion` + `MotionConfig reducedMotion="user"`.

### [2-2] 홈 + 촬영/업로드 + 로딩 + 맥락적 안내 — "첫인상"

- 🦊 스냅이가 인사하는 홈, 큰 버튼 두 개.
- **사진 찍기**는 휴대폰 카메라가 바로 열리고, **사진 올리기**는 갤러리에서 선택.
- 사진을 고르면 영역 지정 단계로 넘어갑니다(아래 UX 개선 참조). 로딩은 전체화면 막이 아니라 인라인 카드로 표시.
- 버튼 아래 🛡 **"사진은 문제를 읽는 데만 쓰고 저장하지 않아요"** — 설정 메뉴에 숨기지 않고 그 자리에서 쉬운 말로 안내(아동 앱 프라이버시 원칙).

> 🔧 개발자 메모: 카메라는 `<input capture="environment">`. 흐름 로직은 `hooks/useAnalyzeFlow.ts`로 분리(화면은 보여주기만, 로직은 훅이 담당).

### [2-3] 판독 확인 화면 — "정확도 1등 공신"

AI가 사진을 **잘못 읽었는데 그냥 풀어버리면** "엉뚱한 문제의 정답"이 나옵니다.
그래서 풀기 **전에** 아이에게 한 번 확인받습니다.

- 스냅이가 "이 문제 맞아? 내가 잘 읽었는지 확인해줘!"
- 올린 사진 미리보기 + 읽어낸 문제를 **큰 글씨**로.
- [✓ 응, 맞아!] → 풀이 시작 / [↺ 다시 찍을래] → 처음으로.
- 사진이 흐려 신뢰도가 낮으면 풀이로 넘어가지 않고 **탓하지 않는 톤**으로 재촬영 유도.

### [2-4] KaTeX 수식 렌더 — "수식 번역기"

"3/4"이나 "90도"를 글자로만 주면 분수가 어그러지거나 기호가 깨집니다.
**MathText**라는 번역기가 문장 속 수식 부분만 골라 **교과서 모양**으로 바꿉니다.

- 분수는 위아래 칸으로, 각도는 °, 곱셈·소수도 깔끔하게.
- 일반 글자는 그대로, 수식만 변환 → 풀이 문장과 자연스럽게 섞임.
- 다크모드에서도 글자색을 따라가 잘 보임.

> 🔧 개발자 메모: `components/math/MathText.tsx`. `$…$`(인라인)·`$$…$$`(블록)·`\(…\)`·`\[…\]`를 파싱, `katex.renderToString(throwOnError:false)`로 안전 렌더. CSS는 `layout.tsx`에서 전역 1회 로드.

### [2-5] 단계별 풀이 타이핑 애니메이션 — "함께 푸는 느낌"

- 풀이가 한꺼번에 쏟아지지 않고 **1.5초 간격으로 한 줄씩** 떠오름(번호 배지 ①②③).
- 마지막에 ✨와 함께 **"정답: …"**을 초록 박스로 강조.
- 학년·단원을 알약 태그로 표시.
- **검산 실패 시**: 억지 답 대신 "이 문제는 자신이 없어, 선생님께 물어보자"라고 솔직히 인정(SnapMath의 핵심 약속).
- "움직임 줄이기"를 켠 기기에서는 애니메이션 없이 **즉시 전체 표시**.

## 3-bis. UX 개선 (실사용 피드백 반영 · 2-R1~2-R4)

기본 흐름 완성 후 실제로 써보며 두 가지를 개선했습니다.

### ✂️ 문제 영역 직접 지정 (선택 사항)
사진 한 장에 여러 문제·이름 등이 섞이면 판독이 흔들립니다. 그래서 사진을 고르면
**"풀고 싶은 문제를 네모로 콕 집어줘!"** 화면에서 사각형을 드래그해 영역을 지정할 수 있어요.
- **[이 부분 풀기]** 지정 영역만 잘라 분석(정확도↑·토큰↓) · **[전체 사용]** 영역 없이 전체로 진행 · **[다시 고르기]** 처음으로.
- 크롭은 **기기 안(브라우저)에서** 처리하고 잘라낸 부분만 서버로 보냅니다(사진 비저장 원칙 유지).

> 🔧 개발자 메모: `react-image-crop` + `lib/utils/cropImage.ts`(오프스크린 canvas로 원본 해상도 기준 크롭). UI는 `components/region/RegionSelect.tsx`. CSS는 `layout.tsx`에서 전역 로드. "전체 사용"이 드래그가 어려운 상황·키보드 사용자를 위한 대안.

### 🧭 진행 단계바 + 인라인 로딩 (동선 명확화)
"지금 어느 단계인지" 항상 보이도록 상단에 **4칸 단계바**(사진→영역→확인→풀이)를 고정했습니다.
- 전체화면을 가리던 로딩 오버레이를 없애고, 로딩을 **해당 단계 카드 안 인라인**으로 표시 → "메인 복귀 후 점프" 느낌 제거.
- 단계 전환은 부드럽게(framer-motion `AnimatePresence`, 움직임 줄이기 시 즉시).

> 🔧 개발자 메모: `components/flow/ProgressStepper.tsx`(status→단계 매핑, `aria-current="step"`, 색+아이콘 이중표시). 상태머신에 `cropping` 추가. 흐름 로직은 `useAnalyzeFlow`에서 `pickImage`(→cropping)와 `analyzeImage`(크롭/전체 공통)로 분리.

### 🐞 함께 고친 버그
- **풀이 중 홈으로 빠지던 문제**: `solve()`가 호출하는 `setError(null)`이 store에서 화면 상태까지 `idle`로 되돌리고 있었음 → store에서 **error와 status 결합을 분리**(에러를 지울 때 화면 상태 보존).
- **503 과부하 시 끊김**: 모델 폴백이 429(한도)만 처리하고 503(과부하)은 못 넘기던 문제 → **429+503 모두** 다음 모델로 폴백·재시도하도록 보강(`generateWithRetry`의 `isTransient`).

## 6. 개발자용 폴더 지도 (Phase 2 추가분)

```
src/
  app/
    page.tsx                    # 상태머신 오케스트레이터 (idle→cropping→…→done) + 단계바
    design/page.tsx             # 디자인 시스템 쇼케이스(검증용)
    layout.tsx                  # ThemeScript + Providers + KaTeX/ReactCrop CSS
  components/
    ui/      Button, Card, Spinner, LoadingDots, LoadingCard(인라인 로딩)
    theme/   ThemeToggle
    providers/ Providers(MotionConfig+테마초기화), ThemeScript(무플리커)
    flow/    ProgressStepper(진행 단계바)
    home/    UploadButtons
    region/  RegionSelect(영역 지정)
    confirm/ ConfirmQuestion
    math/    MathText
    solution/ SolutionSteps
  hooks/
    useAnalyzeFlow.ts           # pickImage(→cropping) / analyzeImage / solve
  lib/llm/
    content.ts                  # 통합 LlmContent·ModelRef + schemaToShape
    gemini.ts / groq.ts         # 제공자 어댑터(OpenAI 호환, Groq 비전)
  lib/utils/
    cropImage.ts                # 클라이언트 크롭(canvas, 원본 해상도 보정)
    generateWithRetry.ts        # 제공자 교차 폴백 체인(429+503 → isTransient)
  stores/
    analyzeStore.ts             # 이미지/결과/상태/미리보기 (error↔status 분리)
    themeStore.ts               # 밝기 선호 + 시스템 감지
```
> (참고) `LoadingOverlay`는 인라인 `LoadingCard`로 대체되어 제거됨.

**스택**: Next.js(App Router) · React 19 · TypeScript · Tailwind v4 · Zustand · framer-motion · KaTeX · react-image-crop · lucide-react.

| UX 동선(라이브 브라우저) | ✅ 업로드→영역지정→판독→확인→풀이 단계바 전이 정확, 인라인 로딩, 오버레이/홈복귀 점프 제거 |

> 관찰 1: 단순 덧셈이 단원 "큰 수"로 매핑되는 등 **내용 매핑의 미세 오차** — 베타 전 커리큘럼 튜닝 루프에서 다듬을 사항.
> 관찰 2: 한 사진에 문제 여러 개가 들어가면 독립 검산이 일부러 `verified=false`(자신 없음)를 띄움 → **영역 지정으로 한 문제만 집으면** 정확히 풀림(설계 의도대로의 안전장치).

## 9. 다음 단계 (Phase 3 예고)

풀이가 끝나면 **"이번엔 네가 풀어볼 차례야!"** 도전 섹션이 등장합니다.
- 유사 문제 풀기 → 정답이면 컨페티 축하 🎉
- 오답이면 정답을 바로 알려주지 않고 **힌트 + 부드러운 격려**로 재도전 유도.
