## 1. 한눈에 보기

Phase 1의 목표는 **화면(디자인)을 입히기 전에, 답을 정직하게 푸는 "두뇌"를 먼저 완성**하는 것이었습니다.

SnapMath의 가장 중요한 약속은 이것입니다:

> **"검산을 통과한 답만 보여준다. 자신 없으면 솔직히 모른다고 말한다."**

교육 앱에서 한 번의 *자신 있는 오답*은 아이와 부모의 신뢰를 무너뜨립니다. 그래서 화려한 UI보다 **정확도 엔진**을 가장 먼저 만들었고, 실제로 그 약속이 작동하는지 진짜 AI(Gemini)로 확인했습니다.

## 2. 스냅이는 어떻게 문제를 푸나? (3단계 파이프라인)

문제를 한 번에 풀지 않고, 사람처럼 **세 단계로 나눠서** 처리합니다.

```
 📷 사진 촬영/업로드
      │
      ▼
 ┌─────────────────────────────────────────────┐
 │ 👀 1단계 · 판독 (Stage A)                      │
 │  사진에서 "문제 글자"만 읽어낸다.               │
 │  "내가 잘 읽었나?"를 0~1 점수로 매긴다.          │
 │                                               │
 │  ▸ 점수 < 0.6  → "사진이 잘 안 보여, 다시 찍어줄래?" (재촬영) │
 │  ▸ 점수 ≥ 0.6  → 다음 단계로                    │
 └─────────────────────────────────────────────┘
      │
      ▼
 ┌─────────────────────────────────────────────┐
 │ 🧠 2단계 · 풀이 (Stage B)                      │
 │  확인된 문제를 학년 수준에 맞게 한 단계씩 푼다.   │
 │  "이건 4학년 1학기 각도 단원" 처럼 교육과정도 매핑. │
 └─────────────────────────────────────────────┘
      │
      ▼
 ┌─────────────────────────────────────────────┐
 │ ⚖️ 3단계 · 검산 (Stage C)                      │
 │  "방금 풀이는 잊고, 처음부터 다시 풀어봐"        │
 │  → 두 답을 맞춰본다.                            │
 │                                               │
 │  ▸ 두 답이 같다  → verified ✅ (화면에 노출)     │
 │  ▸ 두 답이 다르다 → "이건 자신 없어, 같이 물어보자" │
 └─────────────────────────────────────────────┘
      │
      ▼
 🎯 유사 문제도 똑같이 직접 풀어 정답을 확인한 뒤에만 제시
```

### 왜 이렇게 나눴나?
- **판독을 먼저 확인**하는 이유: 사진 수학 앱 오답의 대부분은 "문제를 잘못 읽어서"입니다. 풀기 전에 한 번 거르면 오답의 큰 원인이 사라집니다.
- **검산을 따로 하는 이유**: 같은 풀이를 스스로 "맞나?" 검토하면 자기 실수를 놓치기 쉽습니다. 그래서 **아예 처음부터 다시 풀게 해서(독립 검산)** 두 답을 비교합니다. 두 번 풀어 같은 답이 나와야 신뢰합니다.

## 3. 기능 단위별로 무엇을 만들었나 (1-1 ~ 1-6)

### 1-1. 프로젝트 초기 셋업 🏗️
**비유**: 집을 짓기 전 터를 닦고 골조를 세웠습니다.
- 화면을 만드는 도구(Next.js), 디자인 규칙(파랑·노랑 색, 둥근 모서리, 한글 폰트 Pretendard), 다크모드 기반을 준비.
- 사진·분석 결과를 담아둘 "기억 상자"(상태 저장소) 골격.
- AI 비밀 열쇠를 넣는 안전한 금고 자리(`.env.local`).
- ✅ 확인: 빌드/실행 에러 0건, 브라우저 정상 표시.

### 1-2. 사진 업로드 + 변환 🖼️
**비유**: 아이가 사진을 골라 올리고, AI가 읽을 수 있는 형태로 바꿉니다.
- "사진 올리기" 버튼 → 사진첩 → 고른 사진을 **썸네일로 즉시 표시**.
- 사진을 AI가 읽을 수 있는 글자 데이터(Base64)로 변환.
- 사진이 아니거나 너무 큰 파일(10MB↑)이면 야단치지 않고 다정하게 안내.

### 1-3. 판독 — 스냅이의 "눈" 👀
**비유**: 사진 속 문제를 읽어내는 눈.
- 문제 글자만 추출하고 **이름·점수 같은 개인정보는 일부러 안 읽음** (아동 데이터 보호).
- "내가 정확히 읽었다"는 확신도(`read_confidence`)를 0~1로 매김 → **0.6 미만이면 풀지 않고 재촬영 요청**.
- 라이브 검증: 또렷한 `123 × 45` 이미지 → 확신도 1.0, 일기 문장 이미지 → "수학 문제 아님" → 재촬영.

### 1-4. 풀이 — 스냅이의 "머리" 🧠
**비유**: 교과서를 들고 학년에 맞게 설명하는 선생님.
- 교육과정표(4~6학년 전 단원)를 AI에게 통째로 제공하고 **"그 학년이 배운 방법으로만 설명하라"**고 지시.
- 예: 4학년에게는 방정식·미지수 x 같은 상위 학년 개념 금지. 배운 연산과 그림·표로 설명.
- 한 단계에 한 가지 생각만 담아 차근차근.
- 라이브 검증: 시계 각도 문제 → "4학년 1학기 · 각도" 매핑, 360÷12=30, ×3=90도 (학년 범위 풀이).

### 1-5. 검산 — 스냅이의 "양심" ⚖️ (정확도의 핵심)
**비유**: 답을 한 번 더, 처음부터 다시 풀어보는 신중함.
- 푼 답을 **독립적으로 다시 도출**(별도 AI 호출)해 두 답을 비교 → 같으면 `verified=true`.
- 다르면 `verified=false` + "자신 없음" 신호. **추측으로 답하지 않음.**
- 유사 연습 문제도 정답을 독립 검산한 뒤에만 제시.
- 답 비교는 "82원 = 82 = 1,200원/1200" 처럼 **공백·단위·쉼표를 무시**하는 똑똑한 비교기 사용.
- 라이브 검증: 정상 문제 → `verified=true` / 숫자 없는 모호한 문제 → `verified=false` + "답을 구할 수 없어요".

### 1-6. 전체 파이프라인 검증 🔬
- 업로드 → 분석 → 확인 → 풀이·검산 전체를 이어 호출하고, 결과를 화면에 그대로(JSON) 출력하는 검증 화면.
- 모든 분기(또렷/흐릿, 정상/모호)를 실제 AI로 통과 확인.

## 4. 모델 폴백 체인 — "좋은 모델부터, 막히면 다음 모델로" 🔄

AI 모델을 하나로 고정하지 않습니다. **성능 좋은 모델부터 시도**하고, 그 모델의 무료 사용 한도가 차면(429 오류) **자동으로 다음 모델로 갈아탑니다.** 서비스가 끊기지 않습니다.

기본 순서:

```
gemini-2.5-pro  →  gemini-2.5-flash  →  gemini-2.5-flash-lite
 (가장 똑똑함)        (균형)               (한도 넉넉)
```

- 바꾸고 싶으면 `.env.local`의 `GEMINI_MODELS`에 콤마로 순서를 적으면 됩니다.
- 실제 라이브 로그에서 `pro 한도 초과 → flash로 폴백 → 성공`이 그대로 확인됐습니다. (무료 티어 pro는 한도가 거의 없어 보통 flash가 실제 응답)

## 5. 안전·신뢰 장치 (규칙 5·6 반영)

| 장치 | 내용 |
|---|---|
| 🔒 비밀키 보호 | AI 열쇠는 **서버 안에서만** 사용. 사용자 화면/브라우저에 절대 노출 안 됨. |
| 🧯 친절한 폴백 | 키 누락(503)·요청 폭주(429)·응답 깨짐 등 모든 오류를 아동 눈높이의 다정한 안내로 처리. |
| 🔁 재시도 | AI 응답이 깨지면 1회 재시도, 한도 초과 시 다음 모델로 전환. |
| 🙈 개인정보 최소화 | 사진에서 문제만 읽고 이름·점수 등은 추출 안 함. 원본 사진은 저장하지 않음. |
| ✋ 정직성 | 검산 통과한 답만 노출. 자신 없으면 "모른다"고 인정. 학년 초과 개념 금지. |

## 6. 개발자용 참고 — 폴더 & 파일 지도

```
src/
├─ app/
│  ├─ page.tsx                  # 검증 화면(업로드→분석→풀이 raw JSON)
│  ├─ layout.tsx                # 한글(lang=ko), 메타데이터
│  ├─ globals.css               # @theme 디자인 토큰 + 다크모드(class) + Pretendard
│  └─ api/
│     ├─ analyze/route.ts       # Stage A 판독 API
│     └─ solve/route.ts         # Stage B 풀이 + Stage C 검산 (호출 2회)
├─ stores/
│  └─ analyzeStore.ts           # Zustand 상태(이미지/결과/로딩/에러)
├─ lib/
│  ├─ constants.ts              # 신뢰도 임계값(0.6), 모델 폴백 체인
│  ├─ gemini/
│  │  ├─ client.ts              # Gemini 클라이언트(server-only)
│  │  ├─ prompts.ts             # Stage A/B/C 시스템 프롬프트
│  │  └─ schema.ts              # JSON 응답 스키마(판독/풀이생성/검산)
│  ├─ curriculum/
│  │  └─ curriculumMap.ts       # 4~6학년 교육과정표
│  └─ utils/
│     ├─ imageToBase64.ts       # 이미지 변환 + 형식·용량 검증
│     ├─ normalizeAnswer.ts     # 정답 비교 정규화(공백·단위·쉼표 무시)
│     └─ generateWithRetry.ts   # JSON 파싱 재시도 + 모델 폴백 + 백오프
└─ types/
   └─ analyze.ts                # AnalyzeResult, SolveResult 등 타입
```

### 기술 스택
| 영역 | 사용 |
|---|---|
| 프레임워크 | Next.js 16 (App Router) · React 19 · TypeScript |
| 스타일 | Tailwind v4 (`@theme`) · Pretendard |
| 상태관리 | Zustand |
| AI | `@google/genai` (신규 통합 SDK) · Gemini 2.5 폴백 체인 |

### API 응답 스키마 (핵심 필드)
- **판독(`/api/analyze`)**: `read_confidence`, `extracted_question`, `is_math_problem`, `needs_retake`
- **풀이·검산(`/api/solve`)**: `curriculum{grade,semester,unit,concept}`, `step_by_step_solution[]`, `final_answer`, `verified`, `similar_question{question,correct_answer,hint}`

## 8. 라이브 검증 결과 (실제 Gemini 응답)

| 검증 항목 | 입력 | 결과 |
|---|---|---|
| 판독 — 또렷한 문제 | `123 × 45 = ?` 이미지 | `read_confidence: 1`, 문제 정확 추출 ✅ |
| 판독 — 비수학 | 일기 문장 이미지 | `is_math_problem: false` → 재촬영 ✅ |
| 풀이 + 교육과정 | 시계 각도 문제 | `4-1 · 각도` 매핑, 학년 범위 단계별 풀이 ✅ |
| 검산 — 정상 | 각도 문제 | `verified: true` (독립 풀이도 90도) ✅ |
| 검산 — 모호 | 숫자 없는 문제 | `verified: false` + "답을 구할 수 없어요" ✅ |
| 유사 문항 검산 | — | 4칸×30=120도 / 15-5=10자루 독립 검산 정확 ✅ |
| 모델 폴백 | pro 한도 초과 | `pro → flash` 자동 전환 후 성공 ✅ |
