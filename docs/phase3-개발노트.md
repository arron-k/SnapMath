# SnapMath — Phase 3 개발 노트 (유사 문항 도전 + 정답 루프)

> **목적:** "스냅이가 풀이를 보여준 다음, 아이가 직접 비슷한 문제를 풀어보는" 학습 루프를 비개발자도 이해할 수 있게 정리한 문서.
> **한 줄 요약:** 풀이가 끝나면 → 비슷한 문제가 등장 → 아이가 답을 적고 → 맞으면 컨페티 축하, 틀리면 부드러운 힌트로 다시 도전.

---

## 0. 무엇이 새로 생겼나 (사용자 눈높이)

1. **풀이가 끝나면 도전 문제가 스르륵 나타난다.** 스냅이가 "이번엔 네가 풀어볼 차례야!" 하고 비슷한 문제를 하나 내준다.
2. **답을 적는 칸과 큰 버튼**이 있다. 답을 적기 전엔 버튼이 눌리지 않아 헷갈리지 않는다.
3. **맞히면** 색종이(컨페티)가 터지고 "정답이야! 정말 잘했어!" 축하가 뜬다.
4. **틀려도 혼나지 않는다.** "거의 다 왔어! 여기만 다시 볼까?" 하고 **힌트**를 부드러운 보라색 카드로 보여준다. 정답을 바로 알려주지 않고 다시 풀어보게 한다.
5. 여러 번 막히면 "풀이 다시 보기" 버튼이 생겨 **위에 있는 풀이로 부드럽게 데려다준다.**

## 1. 화면 흐름

```
[풀이 카드: 한 줄씩 타이핑] → (마지막 줄까지 다 보이면)
        ↓ 자동 등장
[도전 카드]
  · 비슷한 문제 (수식 렌더)
  · 답 입력칸 + "정답 확인하기" 버튼
        ↓ 제출
  ├─ 맞음 → 🎉 컨페티 + "정답이야!" (초록 + 파티 아이콘)
  └─ 틀림 → 💡 힌트(보라) + "다시 풀어볼게" 버튼
                 └─ 3번 이상 틀리면 + "풀이 다시 보기" (위로 스크롤)
```

> **중요(규칙 5·검산):** 도전 카드는 **검산을 통과한(verified=true) 풀이**일 때만 나타난다. 스냅이가 자신 없어 한 문제(verified=false)에는 도전을 내지 않는다.

## 2. 새로 만든/바꾼 파일

| 파일 | 역할 |
|---|---|
| `src/lib/utils/compareAnswer.ts` | 아이 답과 정답을 **너그럽게** 비교. 공백·콤마·단위(개·원·cm…)·전각숫자·조사(~이다)를 정리하고, 분수(3/4)·소수(0.75)·대분수(1와1/2)도 같은 값이면 정답 처리 |
| `src/lib/utils/celebrate.ts` | 정답 시 색종이(canvas-confetti). **움직임 줄이기 설정이면 안 터뜨림**(접근성) |
| `src/components/challenge/ChallengeSection.tsx` | 도전 카드 전체(문제·입력폼·정답축하·힌트·재시도). 3-1~3-4를 한 컴포넌트가 담당 |
| `src/components/solution/SolutionView.tsx` | 풀이(SolutionSteps) + 도전(ChallengeSection)을 묶어, 풀이가 끝나는 순간 도전을 등장시키고 "풀이 다시 보기" 스크롤을 처리 |
| `src/app/page.tsx` | done 상태에서 `SolutionSteps` 대신 `SolutionView`를 렌더하도록 교체 |

> 기존에 `SolutionSteps`에 이미 있던 "마지막 줄까지 다 보였어요" 신호(`onAllRevealed`)를 그대로 활용 → 도전 등장 타이밍이 풀이 애니메이션과 자연스럽게 이어진다.

## 3. 디자인·접근성 적용 (claude.md 트렌드 매핑)

- **T1 마이크로 인터랙션:** 도전 카드 페이드인, 정답 축하 스프링 애니메이션, 버튼 호버/탭 scale. 모두 `framer-motion`.
- **T2 감성 UI:** 오답에 부정 표현 0. "거의 다 왔어!" 격려. 힌트/오답은 **빨강 금지 → 보라(gentle)** 톤.
- **T3 게이미피케이션:** 정답 즉시 컨페티(0.5초 이내). 벌칙·경쟁 없음.
- **T5 접근성:** 색만으로 알리지 않음 — 정답=초록+파티 아이콘, 힌트=보라+전구 아이콘. `aria-live`로 결과 읽어줌. 입력칸 `sr-only` 라벨. 버튼 48px+. `prefers-reduced-motion`이면 컨페티·스크롤 애니메이션 생략.
- **T8 AI 짝꿍:** "이번엔 네가 풀어볼 차례야!" 스냅이(🦊) 말투 유지.

## 4. 정답 비교 규칙 (compareAnswer)

같은 답으로 인정하는 예 (실제 테스트 14/14 통과):

| 아이 입력 | 정답 데이터 | 결과 |
|---|---|---|
| `24개`, ` 24 개 `, `24개입니다` | `24` | ✅ 정답 |
| `1,200` | `1200원` | ✅ 정답 |
| `6/8`, `0.75` | `3/4` | ✅ 정답 |
| `1와1/2` | `1.5` | ✅ 정답 |
| `２４`(전각) | `24` | ✅ 정답 |
| `25` | `24` | ✗ 오답 |
| (빈칸) | `24` | ✗ 오답 |

> 단위·공백·조사·전각/콤마를 정리해 "정답인데 형식이 달라 틀렸다고 나오는" 억울한 경우를 줄였다. 의미가 다르면(25≠24) 당연히 오답.

## 5. 함께 고친 버그 / 연관 변경

### 🐞 "풀이 완료 감지" 렌더 경고 수정
도전 섹션을 풀이 종료에 맞춰 띄우려고 `SolutionSteps`의 완료 신호(`onAllRevealed`)를 `SolutionView`에 연결했더니, **렌더 도중 부모 상태를 바꾼다**는 React 경고가 떴다(`Cannot update a component while rendering a different component`).
- 원인: `SolutionSteps`가 `setRevealed`의 **업데이터 함수 안**에서 부모의 `onAllRevealed()`(= 부모 setState)를 호출 → 업데이터는 렌더 단계에서 실행되므로 위반.
- 수정: 카운터 증가 effect와 **완료 감지 effect를 분리**. `onAllRevealed`는 `shown >= total`이 된 뒤 별도 effect(커밋 이후)에서 호출 → 일반 모션·reduced-motion·빈 풀이 세 경로 모두 안전.

### 📷 라이브 카메라 (2-2 보강, 같은 세션)
도전까지 가려면 먼저 사진을 찍어야 하는데, 데스크톱에서 `<input capture>`가 카메라를 열지 못하는 문제를 별도로 보강했다(`getUserMedia` 라이브 카메라 모달 + 파일 폴백). 상세는 Phase 2 영역 — `components/camera/CameraCapture.tsx`. ⚠️ `getUserMedia`는 보안 컨텍스트 전용(`localhost`/https), LAN IP(http)에선 차단되어 자동으로 파일 폴백.

## 5-bis. 도전 흐름 세련화 (실사용 피드백 · C-1~C-5)

처음엔 도전이 풀이 카드 아래 그냥 붙어 "대충 만든" 느낌이었다. 도전을 **화면의 주인공**으로 끌어올렸다.

### 🎯 무엇이 달라졌나 (사용자 눈높이)
1. **풀이가 끝나면 풀이는 살짝 접힌다.** 단원 태그 + "정답: …"만 남고, "풀이 펼쳐보기"로 언제든 다시 본다. 도전 카드가 화면 주인공이 된다.
2. **진행 단계바에 ⑤ 도전이 생겼다.** 도전 중엔 ⑤가 켜지고, 맞히면 초록 체크로 바뀐다 — "지금 도전 단계"가 한눈에 보인다.
3. **틀리면 입력칸이 살짝 흔들리고**(놀리는 게 아니라 "다시!" 신호) 힌트가 뜬다. 답을 적던 게 그대로 남아 바로 고쳐 낼 수 있다.
4. **"비슷한 문제 한 개 더"** — 같은 단원의 새 문제를 받아 한 번 더 연습. 틀렸을 때 특히 유용하고, 맞혔을 때도 더 도전할 수 있다.
5. 입력칸은 **자동으로 커서가 가고, Enter로 제출**된다. 어수선하던 버튼들을 정리했다.

### 🔧 어떻게 만들었나
| 변경 | 내용 |
|---|---|
| `stores/analyzeStore.ts` | `challengeStatus`(idle/active/solved) + setter. 단계바·요약 전환의 단일 신호 |
| `components/flow/ProgressStepper.tsx` | 5번째 스텝 "도전" + `challengeStatus`로 active→solved 매핑 |
| `components/solution/SolutionSteps.tsx` | `collapsible` 표시 모드 추가(요약 헤더+펼치면 즉시 표시). 기존 reveal 애니메이션과 마크업 공유 |
| `components/solution/SolutionView.tsx` | 풀이 완료 시 도전 활성화 + 풀이 접기 + "풀이 다시 보기"(펼치고 스크롤) |
| `components/challenge/ChallengeSection.tsx` | 재설계: 자동 포커스·Enter·흔들림·시도 표시·비슷한 문제 더·정답 후 다음 행동 |
| **`app/api/similar/route.ts`** (신규) | "비슷한 문제 한 개 더" 생성 + **독립 검산** |
| `lib/gemini/prompts.ts`·`schema.ts` | `buildSimilarSystemPrompt`(단원·avoid 주입, 학년 가드)·`VERIFY_ONE`·`verifyOneSchema` |

### 🛡 정확도 장치 유지 (규칙 5)
"비슷한 문제 한 개 더"도 **만든 정답을 그대로 믿지 않는다.** 생성 후 같은 문제를 독립적으로 다시 풀어(`/api/similar`의 2차 호출) 답이 일치할 때만 그 정답을 쓰고, 어긋나면 검산 답으로 교체한다. 라이브 검증: "삼각형 두 각 60·70도 → 세 번째 각?" → 검산 50도, 힌트는 "세 각의 합 180도" (정답 비노출). ✓

### 🔌 Phase 5 연결
`/api/similar`는 지금은 매번 모델을 호출한다. **Phase 5-3(문항 풀 우선 조회)**에서 같은 단원·개념의 검증된 문항을 풀에서 먼저 찾아 재사용하고, 없을 때만 생성하도록 이 라우트 안을 바꾸면 비용↓·출제 일관성↑. (메인 앱 인터페이스는 그대로 — 풀 도입 시 라우트 내부만 교체)
