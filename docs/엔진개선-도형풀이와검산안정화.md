# 엔진 개선 노트 — 도형 풀이 + 검산 안정화

> **언제:** 2026-06-02
> **왜:** 샘플 워크시트(`public/test-problem-2.png`)의 **1번(도형 넓이)**, **3번(분수 문장제)** 이 풀리지 않는 문제를 해결하기 위해.
> **한 줄 요약:** ① 풀이·검산이 **그림을 직접 보도록** 바꿔 도형 문제를 풀 수 있게 했고, ② 답 표기 차이를 흡수하고 검산을 꼼꼼하게 바꿔 **맞는 답이 막히는 일**을 줄였다.

---

## 0. 무엇이 문제였나 (사용자 눈높이)

스냅이가 문제를 푸는 과정은 3단계입니다.

```
[A. 읽기]  사진 속 문제를 글자로 옮긴다
   ↓
[B. 풀기]  옮긴 글을 보고 단계별로 푼다
   ↓
[C. 검산]  같은 문제를 한 번 더 따로 풀어, 답이 같을 때만 보여준다  (← 안전장치)
```

그런데 **B(풀기)와 C(검산)는 사진이 아니라 "옮긴 글"만 봤습니다.** 여기서 두 가지 사고가 났습니다.

| 문제 | 증상 | 진짜 원인 |
|---|---|---|
| **1번 도형** | 못 풂 / "자신 없어" | 그림 속 치수(7·3·5·5·12·8)는 "글자"가 아니라서 읽기 단계가 안 옮김 → **푸는 단계엔 치수가 없었다** |
| **3번 문장제** | 답은 맞는데 가끔 막힘 | 답은 `16명`으로 맞지만, **검산이 가끔 흔들려** 안전장치가 정답까지 막음 |

> 📌 핵심: 1번은 **구조 문제**(그림 정보가 전달이 안 됨), 3번은 **검산 변동성 문제**였습니다.

---

## 1. 무엇을 바꿨나

### ① 풀이·검산이 사진을 직접 본다 (1번 해결의 핵심)

이제 푸는 단계와 검산 단계에 **원본 사진을 함께 넘깁니다.** 그래서 도형·그래프·표처럼 그림에 정보가 있는 문제도 치수를 직접 읽어 풉니다.

- **전:** "다음 도형의 넓이를 구하세요" 라는 글만 보고 → 치수를 몰라 엉뚱한 값(64) 추정
- **후:** 사진을 보고 → `전체 12×8 = 96`에서 `잘린 부분 5×3 = 15`를 빼서 **81 cm²** 를 정확히 도출

### ② 답 표기 차이를 흡수한다 (정답인데 막히는 것 방지)

같은 답이라도 표기가 다르면 검산이 "다르다"고 오해했습니다. 이를 통일했습니다.

- `81 제곱센티미터` = `81 cm²` = `81㎠` → 모두 같은 답으로 인정
- `4 1/12`(4와 12분의 1)를 `41/12`(가분수)로 잘못 붙여 읽던 것 교정
- 단위·띄어쓰기·전각문자 차이를 무시하고 **숫자 값으로** 비교

### ③ 검산을 더 꼼꼼하게 + 한 번 더 본다 (3번 안정화)

- 검산이 "답만 빨리" 내던 방식에서 → **그림의 각 변을 하나하나 확인하고 신중히 푸는** 방식으로 바꿈.
- "~하지 않은", "남은" 같은 **부정 표현**을 한 번 더 확인하도록 지시(3번에서 안경 쓴/안 쓴 헷갈리던 부분).
- **1차 검산이 어긋나면 한 번 더 검산**해서, 두 번 중 한 번이라도 풀이와 같으면 통과(= 다수결). 맞는 답이 한 번의 실수로 막히는 일을 줄임.

### ④ 새로 만드는 "유사 문제"는 그림 없이 글로만 풀리게

도전용 유사 문제가 "오른쪽 그림처럼…" 하고 그림을 참조하면 아이가 못 풉니다. 그래서 **필요한 수치를 문장에 전부 적은, 글만으로 풀리는 문제**로만 만들도록 했습니다. 문항 풀에서 재사용할 때도 이렇게 자기완결적인 문제만 꺼내 씁니다.

## 2. 바뀐 파일

| 파일 | 변경 내용 |
|---|---|
| `src/app/api/solve/route.ts` | 사진을 받아 풀이·검산에 함께 전달 / 꼼꼼한 독립 검산 + 1회 재검산(다수결) |

| `src/lib/utils/normalizeAnswer.ts` | 면적·한글 단위 통일, 대분수 오인 방지, 숫자 값 비교 |
| `src/lib/questionPool/index.ts` | 풀 재사용은 자기완결적인 `generated` 문항만 |

## 3. 지금까지 확인된 것 / 아직 못 본 것

**확인된 것 ✅**
- 풀이가 도형 사진을 읽어 **81 cm² 를 정확히 도출**(이전엔 불가능).
- 단위/대분수 정규화 — 단위 테스트 7/7 통과 (`81 제곱센티미터` = `81 cm²` 등).
- 빌드·타입체크·린트 모두 통과.

**아직 공정히 못 본 것 ⚠️ — 한도 소진 때문**
- 테스트 당시 **Gemini 무료 일일 한도가 소진**되어, 모든 요청이 성능이 약한 **Groq 모델로 폴백**됐습니다.
- 이 약한 모델은 그림 인식·검산이 부정확해, 최근 도형 **검산 통과율(0/3)은 로직 문제가 아니라 모델 품질 문제**입니다.
  (3번이 이전엔 5번 중 3번 통과했다가 지금 안 되는 것도 같은 이유 — 그땐 Gemini 한도가 남아 있었음)

```
[dev 로그 증거]
gemini-2.5-flash 한도(429) → flash-lite 한도(429) → groq:llama-4-scout 로 폴백
```

## 4. 남은 한계와 다음 할 일

- **도형 검산의 본질적 한계:** 검산은 그림을 *독립적으로 다시* 읽습니다. 푸는 쪽은 81로 안정적이지만, 검산 쪽이 그림을 다르게 읽으면 통과가 흔들릴 수 있습니다(완전히 없앨 수는 없는 노이즈). 안전장치(규칙 5: 검산 통과분만 노출)를 유지하는 한 감수하는 트레이드오프입니다.
- **비용:** 정확도를 위해 검산 호출이 1회 늘었습니다(규칙 5 우선).
- **정확한 재측정 필요:** 아래 중 하나로 같은 이미지를 다시 돌려 통과율을 측정해야 합니다.
  1. **Gemini 무료 한도 리셋 후**(보통 하루 단위), 또는
  2. **Gemini 유료 Tier / Vertex AI 전환 후**(실데이터 투입 전 어차피 필요한 단계).
